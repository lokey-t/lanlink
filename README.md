# LanLink · 局域网设备协作

Windows / macOS 作为键鼠主设备，Android 支持受控和远程操作电脑。
离线创建组，通过动态八位数字码或二维码配对；同一局域网内自动发现、加密连接。

**当前版本：0.3.10 原生桌面开发预览。** 包含可运行的桌面服务、Windows 原生模块、macOS
原生模块和 Android 应用源码。自动测试通过不代表三端实机联调完成。
具体编译与验证结果见 [验证记录](docs/VALIDATION.md)。

## 0.3.10 导航、触控板与视野跟随

- 电脑左栏新增「本组设备权限」和「安卓 ADB 授权」；「我的信息」独立显示本机与组身份。协作权限开关从设置移至本组设备权限中的本机卡片；ADB 页面先选择本组手机。
- Windows 触控板使用系统相对输入，保留小数增量，不再反复设置绝对光标位置。被控电脑向当前获准控制者回传真实位置。
- 手机远程窗口增加「缩放画面跟随鼠标」，默认开启并保存选择。靠近当前视野边缘时平移画面；关闭后保持手动位置，正在拖动 / 双指缩放时暂停跟随。
- Windows 远程窗口因切到 ADB 页面等失去焦点后，回来可恢复控制；主动暂停仍保持暂停。输入错误不会再被新视频帧状态掩盖。
- Android 主键点击 / 拖动使用 ADB 触摸事件，右 / 中键补齐鼠标按钮事件；这不使用无障碍服务。输入异常保留真实原因，手机弹窗提供开发者选项入口。小米的额外调试安全权限需用户在系统中开启，软件不会绕过系统限制。
- 升级后仅重启匹配设备私有绑定的旧助手。旧版常驻助手不再使新输入实现失效。

## 0.3.9 持久助手、权限详情与触控板

- 移除安卓无障碍触控备用方案与 LanLink 输入法。手机受控使用 ADB / Root 助手；手机控制电脑仍支持系统键盘输入。
- ADB 助手保存私有绑定并自动重连。电脑记住手动选定的调试设备；手机重启后，已信任的 USB / 无线调试可用时自动恢复，无需重复点击授权。无 Root 且没有调试连接时，不能保证重启后立即可控。
- 桌面「设备详情」汇总本组所有设备的应用开关、系统能力、对本电脑的允许情况；离线与旧版本显示未知，不冒充已授权。
- 修复原生启动入口固定打开旧版的问题；触控板保留微小移动，连接失败时展示原因与重试入口。

## 0.3.8 组与配对

- 统一使用「组」。添加设备默认邀请其他设备加入本组；已有成员时，加入入口显示「解散当前组并加入其他组」。
- 解散会让原组所有成员退出，清除原组连接、授权和布局。先验证新组邀请，错误或过期配对码不会解散原组；界面有明确的二次确认。
- 安卓添加设备页：上方加入其他组，提供相机扫码、手动输入、从图片选择；下方邀请其他设备加入本组，显示动态八位数字、刷新进度和按需显示的二维码。
- 解散通知带设备签名并持久保存。离线成员上线后，需在局域网内遇到至少一台持有通知的原成员，才能同步退出；请所有设备升级到 0.3.8。加入新组和正常重启不会丢失已保存通知。

详细规则见 [组与成员管理](docs/GROUPS.md)。

## 0.3.7 手机控制与 ADB 授权

- 手机使用 Root／ADB 输入助手。0.3.9 已移除无障碍备用触控和 LanLink 输入法；文字通过剪贴板与系统粘贴输入，需要允许剪贴板。
- 电脑点击安卓设备 →「ADB 键鼠授权」，选择调试设备并启用。自动查找已安装的 Android SDK Platform-Tools；手机需先允许 USB 调试、与电脑配对并允许其键鼠操作。不会静默接受系统调试信任弹窗。
- 手机控制电脑时，上方画面可单指移动、双指缩放和移动；画面操作只改变本地视图，下方触控板负责远程鼠标。
- 电脑被控提示位于「我的信息」上方，可直接结束控制。电脑控制手机采用窄边框和右侧工具栏。
- 连接层禁止一边受控、一边反向控制，包括双方同时发起请求和屏幕查看会话；结束已有会话后才可切换方向。

使用步骤和限制见 [手机控制与 ADB 授权](docs/ANDROID-CONTROL.md)。

## 0.3.6 成员管理与手机触控板

- 点击设备可移出组，包括离线设备；移出后需重新配对。每台设备持有独立 RSA 密钥，连接密钥更新分别加密给剩余成员，其他离线成员保留身份。升级前未交换过设备公钥的旧客户端，需要先升级并上线一次。
- 被控端显示正在受控 / 共享屏幕，可主动结束。结束会话后不会被自动重试夺回控制；再次主动请求需要本机重新同意。安卓通知栏也提供结束入口。
- 手机控制电脑：上方画面，下方触控板，底部键盘、功能键、粘贴。支持相对移动、轻点单击、长按拖动、双指滚动和双指轻点右键；中文输入法在组合完成后发送文字。
- 首次同意会开启所选的应用内功能，控制端自动继续。Android 屏幕捕获和 macOS 系统隐私权限仍须本机用户确认，软件不能静默授予。
- H.264 根据往返时间、画面排队延迟和发送积压，在 0.5–8 Mbps 内调整；初始 4 Mbps，拥塞下降、稳定后缓慢回升。Android 直接调整编码器；桌面调整时会重启编码器并等待关键帧，可能短暂停顿。低延迟是优化目标，不能保证弱网下的固定延迟。

说明与边界见 [成员密钥](docs/GROUPS.md)、[串流说明](docs/STREAMING.md)。

## 0.3.5 低延迟视频串流

远程窗口优先建立独立加密视频连接，持续发送 H.264，取消旧版每帧后 180–250 毫秒等待。
键鼠、配对和授权仍使用原控制连接，视频数据不与文件传输共用该连接。
Windows 包已包含 FFmpeg：优先 NVIDIA / Intel / AMD 编码，再尝试系统或 OpenH264 编码；
Android 通过 MediaCodec Surface 编码和解码。目标为 30 fps，实际表现取决于硬件和网络。
Mac 已接入串流接口及可选 VideoToolbox 编码，须在 Mac 配置 FFmpeg 后编译验证。

窗口显示当前串流方式和帧率。不支持视频编码时自动降为 JPEG 连续串流，旧设备仍可使用
截图兼容模式。关闭窗口、断线、撤销屏幕授权或会话过期后停止串流；静止画面保持连接。
首次确认与系统录屏权限保持有效。双方升级到 0.3.5 后可使用新通道。

当前采用独立 TCP / AES-GCM 视频通道，尚非 Moonlight 的 UDP / FEC 协议，也未实现音频、
HDR 或全程零拷贝。验证通过的本机生成画面约 30 fps，并非真实局域网的端到端延迟保证。
实现、构建和验证步骤见 [串流说明](docs/STREAMING.md)。

## 0.3.4 控制确认与权限引导

打开远程窗口即请求控制，等待首次同意或缺失权限时自动重试；拒绝后停止请求，可手动重试。
桌面远程窗口按目标屏幕尺寸与比例打开，超出本机工作区时等比例缩小。手机画面下方有
返回、主页、最近任务三个导航键，需要手机 ADB / Root 输入助手。

首次控制须由被控设备「同意并记住」，可单独取消键鼠、屏幕、剪贴板 / 文件、关机权限。
安卓不提供关机授权项。决定按设备保存在当前组下，重连不重复询问；更换组会清除。
设备菜单中的「重置此设备的本机授权」可撤销，之后需要重新同意。
系统权限独立检查：手机提供开启入口及「已授权」状态；Mac 提供辅助功能、屏幕录制入口。
手机在后台时通过通知进入确认界面，通知未允许时需回到应用查看。

桌面新建组默认开启操作开关，升级时保留已有选择，仍受每台设备的首次确认限制。
设置新增可选登录自启动，默认关闭：Windows 使用当前用户启动项，Mac 使用系统登录项。
Windows 与安卓已编译验证；Mac 已更新源码，需要 Mac 编译、系统授权及登录自启动实测。

## 动态配对码

添加设备默认显示二维码骨架，点击「查看二维码」后才生成并显示二维码。
八位数字配对码直接展示，包含前导零；进度条与倒计时表示距下次自动刷新剩余时间。
每 60 秒刷新，成功使用一次、关闭添加设备或停止显示后均会失效。
点击「加入其他组」展开输入框。已有成员时，该入口改为「解散当前组并加入其他组」，确认并验证邀请后解散整个原组。
二维码与数字码同步更新，不再包含长期组密钥。既有组与已配对设备自动重连不受影响。
新配对需要双方使用 0.3.3 或更新版本，并保持对方的添加设备界面打开。
Windows 原生界面、Android APK 已编译；Mac 界面源码同步，尚未编译或实机验证。

## 内嵌设置与毛玻璃

点击左侧「设备 / 设置」直接切换主窗口内容。设置页分为基本信息、协作权限和应用，
未保存的草稿在切换页面时保留，保存错误直接显示在当前页；运行记录也在页内展开。
设备画布保持原有状态，配对、确认和远程操作继续使用各自的窗口。
侧栏和顶部栏在支持系统 Acrylic 的 Windows 上使用透明底色；设备菜单对背后的应用画面
进行高斯模糊，文字和按钮不参与模糊。系统不支持时保留清晰的浅色界面。
Windows 原生成品已验证；Mac 已同步内嵌设置和原生模糊材质源码，尚未编译验证。

## 启动桌面端

Windows 便携包包含运行环境：**解压整个 ZIP 后双击 LanLink.exe**。
设备管理、配对、屏幕布局和远程操作在独立软件窗口内完成。支持任务栏、
系统托盘和应用菜单；关闭窗口后驻留托盘并返回本机键鼠，退出请使用「退出 LanLink」。
此开发版本尚未进行发布者代码签名。

Windows 界面使用 WPF 原生控件，Mac 源码使用 AppKit / SwiftUI。没有 Electron、WebView 或浏览器界面。
网络服务继续使用随包附带的 Node.js，通过继承的本机管道与界面通信，不开放 HTTP 控制台。
旧版身份和设置自动沿用。Windows 11 支持系统亚克力模糊；较旧系统自动使用浅色背景。

Windows 10/11 需要系统 .NET Framework 4.8 和 Windows PowerShell 5.1。便携包自带 Node.js。
从源码构建使用 scripts/package-windows.ps1 -NodeRuntime <运行环境目录>，该目录需包含 node.exe
和官方 LICENSE / NODE-LICENSE。构建后运行 npm start 或 start-windows.cmd。
Mac 需要 macOS 14+、Xcode Command Line Tools 和官方 Node.js 22+ 发行包。
将 LANLINK_NODE_DIST 指向解压后的 Node 目录，再运行 sh scripts/package-macos.sh。
Mac 原生界面已编写，尚未在 Mac 编译或运行验证，当前不提供已验证的 Mac 成品。
在 Mac 系统设置中允许辅助功能、输入监控和屏幕录制，授权后重启客户端。
关机可能需要自动化权限，未保存文档可能阻止关机。

默认数据目录为用户目录下 .lanlink。可使用 LanLink.exe --data D:\LanLinkData
指定数据目录。默认设备连接端口 45831。--simulate 仅用于开发，禁用原生操作；
--no-discovery 禁用广播发现，仍可手动连接。

Windows 防火墙询问时允许私人网络；日常连接使用 TCP 45831 / UDP 45832、45834；首次数字码配对还使用 UDP 45833 和临时 TCP 端口，请允许应用通过私人网络防火墙。

## 首次配对和使用

1. 在所有设备启动新版客户端，打开「添加设备」。本机八位数字码直接显示，每 60 秒自动刷新。
2. 新设备点击「加入其他组」，输入该八位数字并确认；也可扫描邀请设备显示的二维码，或从图片选择。已有成员的设备须确认解散整个原组。
   安卓也支持系统相机识别 `lanlink://pair` 链接，识别后仍需点击加入。配对期间保持对方的添加设备窗口打开。
3. 各设备按需打开「允许键鼠输入」「允许查看屏幕」「共享剪贴板」「允许关机」。
   桌面新组默认开启操作开关；安卓按需开启系统权限。新设备首次控制还需被控端同意。
4. 点击本机设备，开启键鼠主设备。将顶部设备气泡拖至主设备上下左右，松手自动保存。
   也可在设备菜单中调整方位。拖到已有设备的位置会交换原有方位（新加入布局时替换该位置）。
   点击连接线调整停留时间（100–3000 ms，当前所有边缘共用）。离线设备保留布局。
5. 鼠标停在已设置的边缘后切换。向进入方向的相反边缘移动并停留，可以返回主机。
   随时按 **Ctrl + Alt + F12** 返回本机；Mac 对应 Control + Option + F12，
   某些键盘需要同时按 Fn。
6. 点击设备气泡或画布中的设备，选择「远程控制」即自动请求控制。首次在被控端同意并选择权限；中文和长文本可使用
   专门的文本输入框发送，避免主控与目标输入法状态不一致。
7. 在任一开启共享的设备复制文本/文件。切换后按 Ctrl+V / Command+V 粘贴。
   远程窗口可点「粘贴共享内容」。回到主机时会接收远端最新共享内容。
8. 设备菜单提供共享内容粘贴、发送文件、关机与取消关机。发送文件通过系统剪贴板粘贴到
   目标应用，双方需要相应权限，目标应用需支持文件粘贴。关机在目标端启动 30 秒倒计时。

剪贴板为同身份设备共享，采用「最后收到的复制通知」。动态配对码在有效期内允许加入组，
只交给自己的设备。长期身份密钥保存在本机配置内；没有云端密码找回功能。

## Android

最低 Android 10（API 29），目标 API 35。使用 Android Studio 打开 `android/`，
安装 SDK 35，并使用 JDK 17 / 项目自带的 Gradle 8.11.1 Wrapper 构建：

```sh
cd android
./gradlew assembleDebug
```

首次构建需要联网下载构建工具和 ZXing；安装后局域网功能不依赖互联网。
Windows 使用 `gradlew.bat`；Studio 配置与手机调试见 [Android Studio 调试说明](docs/ANDROID-STUDIO.md)。
仓库还提供 `scripts/build-android.ps1` 作为本机验证用的 SDK + JDK 构建路径。

安卓权限与输入助手：

- 手机受控仅使用 ADB / Root 输入助手。电脑设备菜单的「ADB 键鼠授权」选择手机并启用；手机须先开启 USB 调试并信任该电脑。
- 助手凭据与本机环回端口持久保存，以双向 HMAC 挑战验证连接；服务重启后自动重连。电脑保存设备公钥与所选序列号，后台仅恢复仍属于本组且已允许输入的对应手机。
- 手机重启会终止 shell 助手。已信任的调试连接恢复后电脑自动重新启动助手；没有 Root 或调试连接时不能永久保活。电脑 ADB 页面可取消自动恢复。
- 有 Root 的手机也可自行启动助手；本版不安装系统开机脚本。
- 安卓接收远程文字采用剪贴板和系统粘贴，需允许剪贴板；目标应用须支持粘贴。后台读取剪贴板受系统限制，可切到 LanLink 手动共享。
- 屏幕共享仍需系统录屏确认，受保护内容可能显示黑屏；ADB 输入权限不代替录屏许可。
- 前台通知提供「停止协作」。厂商额外调试权限或安全窗口可能拒绝输入。

详细步骤见 [手机控制与 ADB 授权](docs/ANDROID-CONTROL.md)。

## 当前边界

| 项目 | 当前实现 |
|---|---|
| 网络 | IPv4 UDP 广播发现、TCP 加密直连；手动 IP 连接。访客 Wi-Fi/AP 隔离时需调整网络 |
| 键鼠 | 电脑全局事件捕获，屏幕边缘停留切换；一主机连接多个目标，一次操作一个目标 |
| 屏幕布局 | 每台电脑以主显示器为工作屏幕；暂不支持多显示器拼接及任意屏幕拓扑漫游 |
| 远程画面 | 优先 H.264 低延迟串流，动态码率；不可用时回退 JPEG。无音频和 WebRTC；实际延迟受设备编码和网络影响 |
| 文件 | 普通文件，最多 100 个、合计 2 GB；分块、校验后写入本机接收目录；文件夹需先压缩 |
| 文件粘贴 | 设备菜单发送文件同样通过系统剪贴板，替换当前本机剪贴板；桌面写入系统文件列表；安卓写入带内容 URI 的剪贴板，目标应用必须支持 |
| 传输恢复 | 失败清理未完成接收批次，可重新粘贴重试；尚无跨断线续传 |
| 系统特权窗口 | 不保证 UAC 安全桌面、登录/锁屏、DRM 画面或受保护窗口可操作 |
| 快捷键 | 常见字母、数字、导航、修饰键、功能键；不保证所有媒体键/特殊硬件键与本机完全一致 |
| 剪贴板格式 | 文本与文件；没有 HTML 富文本、图片位图、剪切删除语义；图片作为文件可传输 |
| 组成员退出 | 单独移出设备保留其他成员身份；解散整个组则所有成员退出。离线设备需重新连网并收到签名更新，不能远程即时删除离线设备上的数据 |

这些边界不是“已经实现”的占位接口，超出范围的操作应显示明确错误。
Mac、安卓必须在真实设备上验证权限、输入、显示缩放和文件管理器兼容性。

## 开发和验证

```sh
node --test tests/*.test.js
node scripts/check.js
node scripts/native-smoke.js
```

测试用临时数据、环回连接和模拟原生模块，不执行真实关机。
`native-smoke.js` 只启动原生模块并读取能力，不发送键鼠、读取剪贴板或截屏。

开发专用 HTTP 调试入口仍可通过 npm run dev:http 启动，不属于桌面软件启动流程。
Windows 打包脚本为 scripts/package-windows.ps1，原生桌面回归脚本为 scripts/native-desktop-smoke.ps1。

协议和安全边界见 [架构说明](docs/ARCHITECTURE.md)，实机验收见
[验收清单](docs/ACCEPTANCE.md)。
