# 0.3.45 多设备与弱网修复验证

日期：2026-10-09（Asia/Shanghai）。本次在原有工作树修改基础上修复，保留已有界面、图标、ADB 与远控变更。

## 变更与根因

- macOS 原先每个应用包都会独立创建窗口和启动服务，后启动的包争用同一配置与网络端口。现在在启动界面/服务前按规范化配置目录取得操作系统文件锁，重复启动唤起现有窗口；端口冲突显示明确错误。内核锁在崩溃后自动释放，不删除锁文件造成 inode 竞争。旧包先运行时新版兼容唤起旧包；未修改的旧版后启动仍不遵守新锁，需要更新所有安装副本。
- 组内首次请求原先依赖逐设备允许记录。现在缺省信任当前已认证且未被移出的组内连接；显式保存的禁用项、应用开关、系统权限与单一输入所有者租约仍独立检查。撤销保存全 false，避免删除记录后回到默认允许。临时断线及恢复不会改变决定。
- ADB 引导原先先检查当前电脑的 USB/ADB，才检查手机已有助手。现在优先通过目标加密连接查询手机实时状态，助手已就绪时其他组内电脑可直接复用；不把这一结果冒充当前电脑的 USB 系统信任或保存未经核对的序列号。真正启动助手前通过加密辅助连接核对手机身份。
- 桌面远控窗口原先在选择不同目标时只激活旧窗口。现在同目标复用，不同目标等待旧画面、输入、控制请求和释放完成再切换；迟到释放携带目标 id，快速选择以最后目标为准。
- Android 原先只保留一个 VideoHost/编码器。现在各查看者持有独立会话与订阅，共享一个设备编码源；单个查看者退出不停止其他查看者，码率采用活跃订阅中的最低要求，仍仅允许一个输入来源。耗时 RTC 协商移出全服务锁，关闭和注册通过预约标记协调；旧连接的迟到释放不能影响新连接。
- 鼠标队列按设备隔离，根据 RTT/积压在约 8–50ms 发送间隔内调节；只合并相邻移动，点击/按键构成顺序边界。原始位移只保留约 120ms，累计 Datagram 保留短时丢包恢复，过期点击快照不会补放长时间历史位移。
- 视频以 0.5–8Mbps 为上下限，结合延迟峰值、断流、积压及初始高 RTT 降码率，稳定后缓慢回升；桌面低码率同时降低编码尺寸/帧率，JPEG 联动截图宽度和压缩质量，最低为 640px / 0.35，并以实际字节量限速。心跳不算新画面，不会用陈旧反馈判断网络恢复。
- 文件传输改为约 100ms 预算的小块，TCP/QUIC 共享并发预算，避免 192KiB 块在低速下等待过久导致连接超时。发送端及接收端都为正在进行的远控留出带宽，接收端预算变化时从已校验的偏移重新协商。
- 关闭编码/解码器先关闭管道，再结束所属子进程；750ms 内未退出则强制结束该子进程，避免多次切换残留 FFmpeg。退出等待活跃和已经被替换的编解码器，取消没有查看者的编码器探测；关闭后的迟到画面不会重建解码器。服务关闭等待 TCP/QUIC 正在处理的消息完成再保存配置，防止退出后仍写配置。
- 文件块读取后和应用剪贴板前再次检查来源权限，确保等待最后一个块时撤销授权也会生效。

## 已验证范围

- JavaScript 语法检查通过。最终完整回归 202 项：201 项通过、0 失败、1 项 macOS 图形测试默认跳过；该图形测试另行启用后通过。
- 四个真实加密协议服务实例，模拟两电脑、两 Android 身份：独立目标控制、抢占同一目标时只有一个成功、单设备撤销、断线重连、剪贴板来源保持、迟到关闭不能释放不同目标。
- macOS 实际 Swift 文件锁：8 个竞争进程、不同可执行路径、同一配置目录的软链接、独立配置、强制退出后的锁恢复。
- macOS 实际 AppKit/SwiftUI Model：延迟 acquire、迟到输入错误、A→B→C→D 快速切换，检查目标选择、同窗口复用与释放顺序。该测试使用探针服务，不代表实体手机画面验证。
- 弱网/视频/QUIC/TCP/WebRTC 测试：高 RTT 初始降速、积压合并、鼠标顺序与过期轨迹、断流不误恢复、码率上下限、独立视频会话与关闭隔离。
- 实际本机 TCP 低预算并发文件传输、QUIC/TCP 共享预算、接收端正在控制第三设备时的限速、传输期间开启视频后按偏移续传均通过。
- 实际子进程忽略 SIGTERM 时仍能结束，以及本机 FFmpeg 解码器清理通过。父服务立即退出的整合回归检查 5 个活跃、已退役或探测进程均无残留；探测取消不影响其他查看者，也不污染下次探测结果。
- macOS 原生模块与应用编译通过。最终应用包自带的 Node 运行环境、服务启动、状态读取与正常退出通过；应用包签名验证通过。
- 最终 APK 在独立只读 Android 模拟器 emulator-5556 上安装并验证。三个仪器探针覆盖组内默认授权、显式撤销恢复、首次 ADB 不重复确认、旧连接不能释放新会话、共享编码源、小块传输和弱网输入/码率策略，全部通过。
- 两个真实 Node 电脑服务连接同一 Android 模拟器：A 启动助手后，禁止 B 使用本机 ADB/USB 查询，B 仍可直接使用；两端都实际注入 Android 按键，竞争输入只允许一个来源，显式禁用仅影响指定电脑。真实 RTC 协商期间另一电脑仍能续租，两个电脑均解码到真实 Android H.264 帧，关闭一个查看者后另一个继续获得至少 5 帧；错误的串流 ID 被拒绝。最终脚本自然退出 0。
- 最终 APK 为 0.3.45 / versionCode 36，与已有 0.3.44 APK 签名一致，已验证覆盖安装，无需卸载清除数据。专用 emulator-5556 已关闭；其他聊天正在使用的 emulator-5554 保持原状。


## 实机边界

四设备协议测试使用模拟的系统输入/屏幕，不等同于四台实体设备联调；双电脑对 Android 的实际输入/视频验证运行在模拟器。本机没有 Windows WPF 编译及运行环境，Windows 本次改动仅完成源码复核。实体手机厂商调试限制、实际无线干扰、系统录屏授权仍需按 `ACCEPTANCE.md` 检查。助手就绪可以跨电脑复用；手机重启后助手丢失或主动撤销系统授权时，仍需按系统要求恢复。不能由应用静默授予 macOS 隐私权限、Android USB 调试信任或 MediaProjection。

扩展 RTC 取消测试曾出现一次画面通道提前结束，随后连续三次及最终独立模拟器复测均通过，未确定该次断流根因。交叉复核另外修复了 RTC 多路径重复释放和迟到通道挂接，并保留首次错误日志；不将这些修补宣称为已证实的该次断流根因。实体弱网长时间运行仍需继续验收。
