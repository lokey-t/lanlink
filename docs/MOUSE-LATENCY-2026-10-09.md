# 鼠标低延迟调节补充

日期：2026-10-09。基于当前 0.3.46 工作树；保留其他已经完成的权限、界面、剪贴板及文件修复。安装包使用 `low-latency` 后缀，避免覆盖此前已交付版本。

## 行为变化

| 条件 | 原策略 | 新策略 |
| --- | --- | --- |
| 稳定 200ms RTT，无发送积压 | 增至 50ms | 保持 8ms |
| 一般拥塞或 RTT 上升 | 16–50ms | 通常 12–16ms |
| 持续大积压 | 最长 50ms | 最长 24ms |
| 持续收到空队列反馈 | 可能清零恢复计数，长时间保持降速 | 有足够健康样本后逐步恢复；测试中从 24ms 到 8ms 约 1 秒 |
| 视频协商、文件限速、文字插入 | 处理耗时可能误算鼠标 RTT | 不作为鼠标 RTT 样本 |
| 每秒控制续租 | 等完整回包时阻塞发送队列 | 独立单飞，鼠标继续发送 |
| Android 触控板 | 每次发送完成再等 16ms | 8ms 基础周期，扣除本次发送耗时，不积累补发任务 |

8/12/16/20/24ms 分别对应约 125/83/62.5/50/42 次每秒的调度目标；这不是对实际网络到达频率或端到端延迟的保证。

## 原因与约束

- 鼠标调速依据近期 RTT 增量与实际积压，不再仅因 RTT 超过 120ms 就持续降速。RTT 基线采用 10 秒滚动窗口，辅助通道或网络切换后可以适应新的稳定路径。
- 未提供的反馈字段不冒充零；过期样本不永久维持限速。正常 Datagram 回执可以推动恢复，连续移动不会反复清零恢复进度。
- 续租没有位置或按键顺序语义，因此独立处理；同一连接最多一个续租正在等待。取得/释放控制、移动、点击、按键及输入重置仍保留原有排序与权限校验。
- 移动继续合并为最新位置，旧位移裁剪和点击前位置边界不变；没有为了提速开启无限并发或重放输入。
- TCP/USB 兼容路径的移动仍需等待回应；在高 RTT 环境下，单纯缩短调度间隔不能消除这段网络等待。QUIC 鼠标 Datagram 可直接受益于缩短的周期和续租隔离。
- 本轮没有更改画面码率策略；画面反馈继续用于视频自身调节，不再连带误降鼠标发送频率。

## 验证

- JavaScript 语法检查通过；最终完整回归 231 项，227 项通过、0 失败，4 项需显式图形/Windows 环境的测试默认跳过。本轮未改桌面原生界面代码。
- 稳定高 RTT、拥塞上限、健康反馈恢复、滚动基线、反馈字段缺失、陈旧样本、请求类型过滤、移动合并与点击顺序专项通过。
- 真实加密 TCP、辅助通道及原生 QUIC 回归：被控方刻意挂起续租回包期间，移动与点击均可完成；点击仍等待此前移动处理完成；重复续租复用同一请求。
- Android 在本轮独立模拟器 emulator-5558 上通过自适应策略、加密 TCP/辅助连接延迟续租、纯输入触控板、触控板手势及重连专项。测试后只关闭该独立模拟器。
- 全量测试曾暴露旧视频子进程夹具只等待 1 秒启动且失败时没有及时上报 PID 的问题。本轮仅加固夹具启动等待与失败清理；保留父进程立即退出后无残留的断言，产品视频进程代码未改变。6 项专项和最终全量均通过。
