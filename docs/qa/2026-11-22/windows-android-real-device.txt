真机测试
1. 安装前备份原 APK 和应用内部 shared_prefs/files，随后 adb install -r 当前 debug APK 成功；没有卸载或清空数据，原有组身份继续可用。
2. 当前 Node Service 与手机经实际局域网完成加密认证；独立测试目录复用已有身份，不创建新组，不执行重新配对/解散组。
3. permission-status 返回 input/screen 已启用、系统已授权、对端已允许；ADB engine 持久通道 ready。查询时未申请输入控制。
4. 获取非指针输入控制成功；发送 Home 导航成功，并通过 dumpsys activity 确认前台进入系统 Launcher。
5. 当前 Android 实际采集 -> H.264/TCP -> Windows FFmpeg 实际解码：35,030 ms 内取到 633 个新画面，712 x 1600，首帧 955 ms。约 18.1 个消费帧/秒；这是短时静态/少量动画画面的实际消费数量，不能当作最大帧率、输入到显示延迟或负载测试成绩。
6. 关闭串流并释放输入成功，再次打开后重新得到 H.264 712 x 1600 画面。
7. 另行启动当前编译的 Windows WPF 程序及原生 Windows bridge，实际发现手机，设备菜单显示在线；选择鼠标控制后显示“融合控制中 / 网络”。
8. WPF 原生远控窗口实际显示手机 LanLink 页面；点击窗口自带“主页”按钮后实际画面变成系统桌面，dumpsys activity 再次确认 Launcher。画面指标实际显示 H.264，动态画面曾显示 19 fps / 8.0 Mbps；不把瞬时值当作持续性能结论。
9. 点击远控窗口标题栏关闭按钮后窗口消失，主窗口恢复“键鼠控制：本机”，手机仍在线；末次检查无残留 ffmpeg 解码进程。
10. 安装与测试期间抽查 Android 最近 logcat，未发现 com.lanlink 的 FATAL EXCEPTION 或 ANR；这是有限时间窗口检查。

测试过程中的限制与处理
- 初始安装版 Windows 程序以高完整性运行，自动化无法可靠访问。后续使用独立目录中的当前源码编译版本完成原生界面测试。
- 测试目录通过目录联接复用源码，Node 按真实路径解析模块，初次 WPF 串流未找到 FFmpeg，提示需要 H.264。补齐测试进程的 LANLINK_FFMPEG 后同一源码正常显示真机画面；该次失败属于测试运行目录配置，未判定为产品缺陷。
- 实际全局鼠标控制期间光标被限制在原位；Windows bridge 排除注入键盘事件，自动化发送 Ctrl+Alt+F12 没有触发物理紧急返回分支。结束该轮测试进程后确认输入已释放；物理紧急快捷键本轮未验收。远控窗口关闭释放则已实际验收。
- 第一段自动串流测试的桌面 Native 为禁止本机输入/屏幕/剪贴板的测试适配器，手机为实际生产路径；随后 WPF 测试使用实际 Windows NativeBridge 与真实手机，补充验证原生呈现和导航。
- 本轮测试配置关闭桌面剪贴板自动上传/下载，不修改用户原配置中的开关。
