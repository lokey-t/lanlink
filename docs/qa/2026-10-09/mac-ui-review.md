# Mac 原生操作测试记录

2026-10-09，macOS 15.7.7，arm64，当前 0.3.45 工作树。使用当前 `LanLink.swift`、`SingleInstance.swift`、`Remote.swift`、`AdbGuide.swift`、`Staging.swift` 编译的测试副本。服务源码与当前工作树一致；Bundle ID 改为 `com.lanlink.qa20261009` 隔离偏好，配置位于 `/private/tmp/lanlink-deep-qa-20261009/profile`。这不是正式发布包验证。

启动参数为 `--simulate --no-discovery --port 0`。原生 UI 通过电脑操作工具点击；三个测试成员使用本机真实加密连接，系统能力使用模拟对象。文件和剪贴板内容为临时生成。

## 完成的操作

| 场景 | 实际结果 |
| --- | --- |
| 启动和设备页 | 显示本机及“设备服务已连接” |
| 名称字段草稿 | 切换设备页再返回设置，草稿保留 |
| 名称为空 | 保存显示“设备名称应为 1–80 字符” |
| 中文名称 | `QA Mac 深度测试` 保存成功并更新本机展示 |
| Command+A | 名称字段按快捷键后输入 Z 或 T，字符追加到原值末尾，未替换原文；窗口恢复前台后再次重现 |
| 粘贴 | 在名称字段执行粘贴 `PASTE-TEST`，字段仍为原值；该工具会恢复此前系统剪贴板 |
| 菜单 | AX 菜单栏仅 LanLink、View、Window、Help，无编辑菜单 |
| 配对 | 显示八位码及倒计时，二维码可展开/隐藏；示例码有前导零 |
| 配对格式 | 将字段设置为 `0012ab34 56` 后显示 `00123456`；输入 `0012` 后提交，有原地八位校验提示 |
| 手动连接非法地址 | `bad host!` 提交后本页无错误；设备页显示“设备地址或端口无效” |
| 手动连接不存在主机 | `not-an-ip` 提交后设备页显示“正在连接设备”，无最终失败反馈；源码吞掉 socket 错误 |
| 手机菜单 | 无“撤销此设备的本机权限”；同场景 Windows 身份成员有此项 |
| 布局 | 将模拟 Windows 成员放右侧，显示“布局已保存”，本机成为主设备 |
| 离线 | 停止模拟 Windows 服务后成员和右侧布局保留，控制/粘贴/文件/关机按钮禁用 |
| 文件接收 | `QA 测试文件.txt` 30 字节、`QA 空文件.txt` 0 字节均显示已接收 |
| 剪贴板历史 | 中文、emoji 与换行显示正确；点复制显示“已复制到本机剪贴板”，写入模拟桥接 |
| 外观 | 浅色立即应用，文字及开关可读 |
| 关闭与恢复 | 点关闭隐藏主窗口；从 Finder 打开该测试副本恢复原窗口 |
| 服务退出 | 结束本轮拥有的子服务进程，设置页无变化；设备页显示“设备服务已退出，请重新启动 LanLink” |
| 清理 | 退出 QA 应用，结束本轮三个模拟服务；未结束其他服务 |

## 边界

未通过这个副本读写真实系统剪贴板、执行屏幕采集、注入真实键鼠、操作用户设备组、自启动或关机。设备状态中的未就绪与模拟系统能力相关，不据此报产品缺陷。

测试中部分窗口截图右侧出现捕获空白，未确定是窗口位置还是捕获限制；没有把它列为软件显示问题。快捷键在名称字段实测，报告中对其他输入框列的是待回归范围。

报告事实对应 `mac-settings-ax.txt`、`mac-invalid-host-*.txt`、`mac-service-exit-*.txt`、`mac-android-device-menu.txt`。这些文件来自操作后的原生无障碍树；部分为相邻状态差异，应按成对文件阅读。
