# 鼠标远程控制性能改进与验证

日期：2026-10-11。修改基于工作区当时的已有改动继续进行，没有回退其他功能。

## 实现

- **可靠操作与移动解耦**：新版本 QUIC 对端通过 `motionV2:2` 协商。允许移动越过正在等待回复的一个点击、滚轮或键盘请求；下一条可靠输入、释放及会话切换仍等待前一条完成。移动包携带 `afterInput`，可靠输入携带会话与序号；接收端只在依赖的操作执行后应用移动。可靠输入失败会结束该 QUIC 控制路径，避免按键状态不明确时继续控制。续期不等待点击回复。
- **二进制热路径**：三端共用 104 字节、网络字节序的移动记录，包含会话、序号、时间、依赖序号、累计/近期位移、位置及年龄。该记录直接穿过 C ABI / JNI 和 QUIC；接收事件也通过二进制记录返回。鼠标移动的这段链路不再使用 JSON / Base64。低频请求、视频本地封装仍保留现有格式。
- **事件唤醒**：共享 Rust 网络线程使用 UDP 可读事件、命令唤醒和 QUIC 截止时间，不再固定休眠 2ms。应用侧通过条件变量等待事件，取消新原生库上的 4ms 定时轮询。100ms 是空闲等待上限，事件到达会立即唤醒；关闭时等待正在进行的原生读取结束后释放句柄。
- **自适应移动节奏**：健康状态下最小发送间隔从 8ms 改为 4ms，拥塞上限仍为 24ms；Android 触控板也使用新的最小间隔。合并不能越过按下、松开等边界；累计位移补偿和过期移动丢弃策略保留。
- **减少本地转换**：macOS / Windows 原生进程的移动捕获和注入采用协商后的紧凑行格式；Android 输入助手采用有版本判断的紧凑格式，区分绝对坐标和原始位移。进程隔离、权限检查和错误回复保留，没有将系统输入模块强行合并到应用进程。
- **批量跨进程输入**：一次丢包补偿产生的多段移动，可以在一个原生/助手请求内执行，最多 64 段，避免逐段等待进程通信回复。旧原生模块或旧 Android 助手继续逐段执行。
- **视频让路**：共享 QUIC 引擎将视频填充门限降到 8 个 Datagram / 8KiB，将已生成但等待节奏发送的 UDP 包限制为 16 个，并为可靠控制流设置较高优先级。新移动快照替换尚未发送的旧二进制移动。视频与输入仍共享连接和物理链路，没有声称完全隔离拥塞。

旧版本、缺失新原生库、TCP 和 USB 路径保留兼容行为；可靠请求等待的解耦目前只在双方支持新版 QUIC 输入协议时启用。紧凑本地输入也适用于 TCP / USB；批量恢复目前由 QUIC 补偿路径调用。

## 验证结果

- 完整回归：**297 项，293 通过、4 跳过、0 失败**。跳过项为需要另行启动桌面 UI 的 macOS 用例。
- macOS：共享 QUIC 原生库及完整 Swift 输入桥编译通过；真实回环 QUIC、乱序/丢包、权限撤销、点击等待与视频/文件回归通过。
- Windows：原生输入模块和桌面应用通过 C# 5 / .NET Framework 4.8 编译；调度、输出背压、紧凑移动回调及按钮边界逻辑测试通过。**本机不是 Windows，未构建新版 Windows QUIC DLL，也未进行 Windows 系统输入实测**；发布前须在 Windows 运行现有 QUIC 构建与打包脚本，并实测跨屏操作。
- Android arm64：JNI 原生库、应用及测试 APK 编译通过。模拟器验证了桌面/Java 共用二进制字节样例、JNI 传递、点击回复与移动/续期并行、释放顺序、丢包补偿、批量 uinput 输出、自适应节奏和触控拖动/取消。
- 桌面 ↔ Android：确认协商 `motionV2:2`；真实 ADB 助手执行鼠标位置和点击坐标正确；同时验证 QUIC 文件内容哈希以及 10 帧 H.264 屏幕传输/解码。
- 两个原有测试的调度竞争已稳定：暂存重启检查等待保存任务完成，重复续期检查等待第二调用者实际加入在途请求。

日志见 [验证记录](qa/2026-10-11-mouse-performance/)。Android 调试包在 `android/app/build/outputs/apk/debug/app-debug.apk`。

## 本机传输格式对比

使用 `scripts/motion-benchmark.js`，每组 200 个样本，跳过 20 个预热样本；两种格式都运行在本次修改后的原生引擎上。视频负载为每 40ms 发送一个 24KB 模拟帧。单位为毫秒。

| 本地传输路径 | 模拟视频负载 | P50 | P95 | P99 |
| --- | --- | ---: | ---: | ---: |
| JSON / Base64 兼容路径 | 无 | 0.352 | 0.593 | 0.975 |
| 二进制路径 | 无 | 0.317 | 0.568 | 1.082 |
| JSON / Base64 兼容路径 | 有 | 0.301 | 0.546 | 0.755 |
| 二进制路径 | 有 | 0.219 | 0.356 | 0.493 |

这是同一进程内两个原生端点的回环传递测量，包含格式转换和事件分发，**不包含真实 Wi-Fi、系统输入注入或显示延迟**。单轮少量样本存在调度噪声，无负载 P99 没有改善；不能据此承诺三端实际总延迟或所有情况下的性能提升。

复测：完成原生构建后运行 `node scripts/motion-benchmark.js`。可用 `LANLINK_BENCH_SAMPLES` 调整样本数。
