# 数据线与网络协同（0.3.19）

设备先在同一组中建立局域网连接。辅助通道不会代替配对或首次控制许可，也不会将同一次点击、按键重复发往两条线路。

## 电脑 ↔ 安卓

Windows / macOS 安装 Android SDK Platform-Tools，手机开启 USB 调试并信任这台电脑。已联网的同组安卓设备会每隔约四秒检测辅助通道。只选择就绪的物理 USB 调试设备；无线 ADB 和模拟器不计作数据线。即使使用 Root 输入，也需允许电脑 USB 调试，才能使用这条线传输。

电脑通过 ADB forward 建立独立的加密控制连接。手机端只监听回环地址，并核对原局域网设备身份和每次随机生成的通道密钥；同组另一台手机或插错线不能接管目标设备。原有组权限、控制所有权和互斥检查仍然执行。

键鼠指令双向可走数据线。电脑查看安卓画面使用 ADB forward；安卓查看电脑画面使用 ADB reverse。画面仍经过原有加密视频协议，不改变 H.264 编码和自适应码率机制。剪贴板、设备发现和协商继续使用局域网。

## 电脑 ↔ 电脑

支持系统已识别为 IP 网络接口的有线连接，例如网线、雷电网络、USB 网络适配器或能提供网卡接口的桥接设备。两台电脑都需升级至 0.3.19。

软件在各 IPv4 接口上进行同组发现。如果在原有连接之外发现同一设备的另一个地址，会建立并认证辅助通道，比较往返耗时后选择键鼠路径；新建桌面控制画面也使用选定的地址。界面显示「双网络 · 低延迟通道」。不能仅根据网卡名称断言它一定是数据线，因此界面不把所有第二网络都标成 USB。

普通 USB 数据线将两台主机相连，如果操作系统没有生成可通信的网卡接口，本版本不能把它变成主机间通信设备。需要专用驱动 / SDK 且不提供 IP 接口的传输线尚未适配。

## 选择、回退与边界

- 建立通道时采样三次往返耗时，后续定期检查。辅助通道更慢时保留局域网；当前辅助通道明显变慢或失效时退回局域网。
- 控制请求按顺序发送，移动事件仍保留原有合并机制。不进行双路重复注入，也不重放结果不确定的点击、文本或按键；断开时释放按住状态，后续输入走局域网。
- 画面按会话选择路径。数据线中断会结束当前画面传输，由已有重连流程重新协商；不保证每一帧都无缝延续。连接过程中插线后，新画面会话使用选定路径。
- 原局域网连接承载设备身份、协商与会话生命周期，需要保持在线；本次未实现完全脱离局域网的纯 USB 模式或把两条线路带宽相加。
- 临时 ADB 转发只移除本软件创建的具体端口，不清空其他工具的转发规则。

底层端口转发参考 [ADB 官方命令文档](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)。
