# 0.3.47 同组布局与混合设备控制

## 使用方式

同组的 Mac、Windows 和 Android 都应更新到 0.3.47；旧端不具备完整布局显示与多级跨屏逻辑。

在任一端的设备布局中，将主控电脑放入布局，再将其他设备摆到任意已放置设备的上、下、左、右。所有端显示相同的设备坐标和“主控电脑”标识。点击布局中的 Mac 或 Windows 卡片即可将其设为主控，同组其他设备自动更新标识；手机不能设为跨屏键鼠主控。桌面拖动卡片可调整位置，右键保留设备操作和相对摆放菜单；手机长按设备可选为摆放参考。布局允许多条分支，例如：

```text
主控 ─ A ─ B ─ D
       │
       C
```

选定主控电脑的物理鼠标可以沿图中相邻屏幕连续移动。鼠标从 A 进入 B 时，仍由主控电脑直接连接 B，不经过 A 转发键鼠。选择新的主控后，各端同步主控标识并释放旧的跨屏控制；设备坐标保持不变。普通窗口内的远控和手机触控板继续使用原有权限检查。

布局和主控选择只在同一配对组内同步。布局最多保存 64 个设备位置，横纵坐标各在 -32 至 32 内，每格只放一台设备；不相邻的位置没有跨屏连接。移出布局不会移出配对组。主控或当前被控设备被移出布局时，鼠标返回本机。

正常心跳仅交换布局版本摘要；重连、版本不一致或尚未接收相关成员信息时重新补发完整图。显式选择主控总是生成新的修订，避免被迟到的旧端初始化状态覆盖。离组后，旧连接不再接收新组布局，也不能以旧凭据恢复成员或请求默认权限。

## 延迟与连接修复

- Windows 原生输入不再等待 16ms 定时轮询；截屏编码和剪贴板使用独立工作线程，减少对输入线程的阻塞。
- 两个桌面端的输出不再由输入回调直接等待。可靠按键、点击和回复保持顺序；连续移动合并，旧位移按 120ms 窗口裁剪，截图与未完成命令有容量限制。
- 多设备共用 QUIC 时，总待处理命令仍限制为 64；普通命令最多 48、每个连接普通请求最多 24。等待网络回复的请求总数最多 56，每连接仍最多 32，给本机回复、鼠标和关闭操作保留容量。短暂本机繁忙不再立即退出控制或关闭画面。
- 鼠标发送仍为 8–24ms 自适应，改善的是额外等待和跨设备互相占用容量，没有通过无限增加发送频率来掩盖排队。
- Android 未接通的辅助通道不再因空引用相等而释放正在使用的鼠标；旧通道关闭或迟到失败不会清除替换通道。续租遇到通道替换后，最多重新确认一次当前通道；两条通道都失败仍结束会话。
- 没有活动会话的权限变更不发送过期的结束通知；有会话时使用会话标识，防止旧通知取消同一设备的新会话。

## 验证依据

本轮新增真实加密连接测试，覆盖五设备的串联、分支、反向返回、切主控、非主控拒绝、修饰键及点击顺序、切换准备期间反向移动取消、离线邻居、目标拒绝和迟到通知。同步测试覆盖同时编辑后的收敛、离线重连、旧版本布局迁移、外组数据拒绝与成员移除。

三端原生 QUIC 压力测试重现了原先两个连接的请求占满全局名额后拒绝鼠标的问题，并验证修复后普通请求受限、鼠标和可靠点击仍能发送；在 32＋24 个请求等待网络回复时，回复和关闭仍有可用名额。

Android 在独立模拟器上运行真实 JNI 与辅助连接探针。两套独立 Node 控制端分别模拟 Windows USB 与 Mac 局域网身份；Windows 通过实际 ADB 转发保持加密辅链，另一端禁用 ADB 后取得原生指针控制。跨未连接辅助通道实际超时以及 Windows 辅链关闭期间，虚拟鼠标设备标识保持一致，并观察到 42 个 Android 内核 REL_X 事件。该验证不等同于实体 Windows、Mac 和手机的完整体验测试。

Mac 原生桥与应用编译、桌面输出调度探针，以及 Windows 同源码调度探针与 C# 5 / .NET Framework 4.8 交叉编译均有独立检查。Windows 的真实系统 Hook、剪贴板 STA 和 WPF 窗口仍需在 Windows 上验收；实体设备弱网的端到端延迟没有在本机测量，不给出未经测量的提升百分比。

2026-10-10 最终全量回归：291 项通过，0 失败，0 跳过；包括启用的 Mac 原生界面测试、Windows 同源码逻辑探针与 Framework 4.8 编译。JavaScript 语法检查和 diff 空白检查通过。Android 最终辅助通道隔离、QUIC、组内授权和共享布局四组探针均通过；真实 Android 加密组网测试还覆盖手机修改布局向两台桌面端传播、主控切换后旧指针会话结束与旧主控被拒绝。
