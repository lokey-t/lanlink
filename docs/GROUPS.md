# 成员身份与离线更新（0.3.6）

每台设备保留 UUID、RSA-2048 公私钥；组标识不随连接密钥更新而变化。短码 / 扫码仍走 SRP，会话内交换设备公钥及组信息。
成员注册附有邀请设备签名的公钥证明。更新发送者在接收者离线期间新加入时，可通过这条证明链验证身份；不要求最初的邀请设备一直在线。
这不是在线账号系统，不依赖云端服务器。

## 移出与恢复

移出操作清理布局、设备记录、该设备授权，生成新连接密钥，关闭原控制与视频会话。
在线被移出设备立即回到独立身份；离线被移出设备持有的旧凭据无法连入更新后的组，需要再次输入短码或扫码加入。
移出设备时不会给它生成新密钥更新。

每个剩余成员有独立更新信封：随机 AES-256-GCM 密钥封装连接凭据和成员快照，以接收者 RSA-OAEP（SHA-256 / MGF1 SHA-256）公钥包裹 AES 密钥，
发送者 RSA-SHA256 签名绑定组、接收者、版本、封装密钥和密文。接收者检查公钥证明、签名、版本、身份、成员上限，然后持久化并重连。
私钥、明文连接凭据均不通过发现广播发送。设备私钥存放于桌面本地配置或 Android 应用私有存储，未引入外部账号或系统级钥匙串依赖。

UDP 45834 每两秒发送小型恢复探测；有更新的成员仅向请求者回复匹配接收者的加密信封，限制重复响应。
保留签名历史更新，离线设备按版本补齐；任一持有相应更新的剩余成员都可提供恢复。没有任何持有新状态的设备在线时，需要等待其上线。
已消费或签名损坏的更新不改变本机身份。公钥证明链只证明设备密钥来源，当前成员状态和本机功能授权仍单独检查。

## 升级与实现边界

- 旧版本没有设备公钥，须先升级并上线一次交换公钥；没有剩余成员公钥时，移出操作会明确报错，不会让它们意外失去身份。
- 开发预览限制每组 16 个成员、64 个移出记录、最多 64 轮历史更新及约 1.5 MB 历史记录预算。达到上限会停止新增变更并提示处理；不会静默丢弃离线恢复所需记录。
- 当前组内成员视为互相信任，日常连接仍沿用组密钥认证。成员变更应逐次完成；网络分区中同时修改组成员尚无分布式冲突合并保障，需人工重新配对收敛。
- 实现尚未经独立密码学安全审计，不用于不互相信任的组织成员权限隔离。
- 自动化覆盖加密、签名、公钥证明、过期版本拒绝、离线恢复、在线移出和重新配对；真实多机广播、防火墙和长时间网络分区仍需实机测试。


## 0.3.8：切换组会解散整个原组

界面不再使用「账号」。只要已有其他成员、历史设备，或成员变更记录，就视为已经成组，邀请页默认让其他设备加入本组。转入其他组须明确确认「解散当前组并加入其他组」。

先完成新邀请验证和元数据校验，再记录待完成加入与签名解散通知，最后结束控制、通知原成员并切换。配对码错误、过期、取消或原组状态发生变化不会触发解散。成功扫描只填入邀请，仍需用户提交确认。原组自己的邀请不会解散自身。

解散通知使用 RSA-SHA256，签名覆盖协议标识、稳定组 ID、版本、发起设备 ID；附带已有的成员证明链。只接受当前组可信且未撤销的成员签名，通知不包含连接凭据、私钥或设备显示名称。解散是该组 ID 的终态，不能被迟到的成员更新恢复。

在线设备处理通知后各自建立独立的新组，清除原组已知设备和授权。签名通知保存在桌面配置的 dissolvedGroups、安卓私有配置的 dissolved_groups；切换组、退出或正常重启后继续保存。UDP 45834 的恢复查询可返回此前组的解散通知。

离线设备只有重新联网、与至少一台保存通知的原成员处于可互通局域网时才能退出。若保存通知的设备均离线、被卸载或清除了数据，通知暂时无法传达；并不存在云端后台撤销。离线同步要求各成员升级至 0.3.8。最多保留 64 个组的解散记录，达到上限时拒绝新的解散，避免静默丢失离线通知。

旧配置和成员密钥沿用。内部 accountId 与 state.account 别名暂保留以兼容已有调用方；当前界面与新增接口使用 groupId、groupEstablished。单独移出某台设备仍是另一项操作，不会解散整个组，也不会要求其他离线成员重新配对。
